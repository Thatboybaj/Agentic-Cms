03 · Architecture

Layering

Applicationapps/cms/convex/*: access checks (requireSiteRole), post state machine (posts.transition), gate and autopost decisions (reused from logic.ts), audit, notifications.
Capabilities@studio/seo-harness (roster, routing, skills) · @studio/web-tools · @studio/storage R2 port · src/render renderer · pure parts of the visual agent.
Effect fencecappedInference for all text and image spend · spend ledger debit, credit, reconcile · message delivery (v1.1).
PlatformConvex (+ Workflow, Workpool, R2, Rate Limiter, Autumn, Polar) · Clerk · Vercel · Anthropic · image providers · GitHub/GitLab · Google · Langfuse · Sentry · PostHog.

Call shape everywhere: action → Effect program → mutation. Actions orchestrate and return typed results; one internal mutation persists each step. The browser only ever calls Convex functions with the Clerk token.

Tenancy and isolation

Workspace = Clerk organisation. Site roles are Convex memberships. Effective role: workspace owner or admin → admin on every site; otherwise the membership role; otherwise no access. Every public site function is registered through a wrapper that calls one helper first:

requireSiteRole(ctx, siteId, permission) 1 identity from the Clerk token → "Not authenticated" 2 user row, not suspended 3 site row → "Not found" (same as no access) 4 site.workspaceId = token's active org 5 role = effectiveRole(workspace role, site membership) 6 PERMISSIONS[permission] includes role → FORBIDDEN + the UI's lock reason
#Isolation rule
I1Every public site function takes siteId first and checks access before any read
I2Child records are read through their parent, after checking the parent belongs to the site
I3Tenant tables are only queried by a by_site index; no whole-table reads
I4Agent context is built from one site only; a step refuses input from another site
I5R2 keys are prefixed sites/<siteId>/; URLs minted only after the access check
I6Secrets decrypt only inside internal actions and never reach prompts, logs, audit or Langfuse
I7Webhooks resolve the tenant from the provider payload, never from the URL
I8"Doesn't exist" and "not yours" return the same error
04 · Post lifecycle

A chain of short workflows, not one long one

States and transitions stay exactly as in logic.ts. A human pause (review, merge) is a row state, not a sleeping workflow. Only posts.transition(postId, from, to) moves a post, and it checks from, so a late step can't undo what a person already did.

approveIdeaAccess check, idea → briefed, audit
→
postPipelineDraft, optimise, fan out visual agent per image slot (Workpool)
→
autopostGateevaluateGate → fixes → re-evaluate → ship or hold
→
shipPostRender → branch content/<slug> → commit → open PR
→
WebhooksCI green → auto-merge → live → KAS after 24 h

Holds

Autopost off, no repo, no confirmed template or it can't render the post, over cap, provider failure, an image slot for a person, an unfixable hard check. Each writes an "Autopost held" ledger item and notifies specialists.

Scheduling

One cron ticks every 5 minutes over per-site schedule rows (in the site's timezone, pausable). The Haiku orchestrator is replaced by deterministic code (D6). "Run now" uses the same workflow as the cron.

Agent execution model

Agent = workflow stepA Node action agents.<id>.run({ siteId, runId, inputs }): builds single-site context, calls the model through cappedInference, validates the structured output and returns it. The next mutation persists it.
CMS agentNot an LLM loop. It is the workflows, posts.transition and gitNode.* (the only repo writer). It calls a model only for autopost fixes, at the workhorse tier.

EscalationStatic from the harness config (writer → strongest for pillar and money pages; report → strongest on pivot). Dynamic (D7): invalid output → retry once → one tier up if the cap allows → else fail and hold.
BudgetsassertWithinBudget before every turn of a multi-turn step; maxTurns set explicitly per agent.
ToolsWeb research cheapest-first; image providers through HTTP MCP or APIs. No code execution, so no sandbox. Agent SVG goes through sanitizeSvg().
GuardrailsFact markers for unsourced claims, regulated disclaimers, no invented credentials. Images: no real people, no living-artist styles, no watermarks, licence check and provenance, estimate before running.
06 · The inference fence

Every paid call goes through one program

EstimateestimateRun per kind and site
→
Cap checkAllowed · warn at 80% · refused (post holds)
→
Rate limitPer site and per workspace
→
Autumn checkEntity = site
→
Debit estimateIdempotency key built on the server
→
Call + retryBounded backoff on 429, 5xx, timeouts
→
SettleCredit the difference or debit overage once; refund on failure
  • Two monthly budgets per site: text and image, in USD, set by an admin. Over cap refuses with a message; nothing is billed silently.
  • Ledger truth is spendEntries in integer micro-USD. Autumn is the commercial meter, reconciled daily.
  • Customer-supplied provider keys are still estimated and capped, but debited as zero provider cost plus any CMS fee (D15).

Observability

SignalContent
LangfuseOne trace per run, spans per model or tool call; tagged site, workspace, agent, tier, skill hash. No secrets, no personal data.
SentryServer and client errors tagged with site, run and workflow

FailureBehaviour
Model call failsBounded retry inside the fence → refund → run failed → post holds "Provider failure"

Base branch movedRebase re-renders from the current template; a conflict notifies the developer; never force onto base
