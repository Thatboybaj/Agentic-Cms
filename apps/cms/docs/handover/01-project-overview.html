01 · Summary

What this is

Agencies run SEO blogs for many clients. Today each post means a writer, a designer, an SEO check and a developer pasting HTML into the client's codebase. The Agentic CMS removes everything except the decisions that need a person.

1human decision per post by default: approving the idea
11 + 1harness agents plus the CMS agent that owns the repo
8client sites seeded in the demo workspace, 7 people
156automated tests passing; type-check and production build clean

The promise

Run a client's entire blog programme without opening a code editor. Every post lands in the client's own site template, through a normal merge request, with every claim sourced and every action audited.

What's been delivered

  • A full working frontend prototype for many sites and many users
  • A design system built from the reference screens
  • The SEO harness packaged into the monorepo
  • A backend blueprint, schema and ten ordered build handoffs
02 · How a post moves

Only ideas need approval

Autopost is on by default for every site. A person approves the idea; the agents do the rest, and stop for a person only when a guardrail fires.

IdeaFrom keyword research, a ranking gap or a person. A specialist approves it.
→
DraftWriting agent drafts in the site's brand voice, marking every factual claim.
→
ImagesVisual agent generates, diagrams or sources images, with provenance.
→
GateSEO checks run. Agents fix what they can, and source or rewrite unsourced facts.
→
Merge requestRendered into the client's template, committed on its own branch.
→
LiveMerges itself when the client's CI is green. Ranking measured after 24 h.
When a post is held it stops at In review with the reason on the ledger. Reasons include a hard check that can't be fixed, no repo, a template that can't render the post, a budget cap, a provider failure, or an image slot marked for a person.
When autopost is off for a site, every post stops at In review for a specialist to approve, and a developer merges. Auto-merge itself is an admin-only setting.
03 · Who uses it

Roles are per site, not global

One person can be a specialist on four sites and have no access to the rest. Workspace owners and admins act as admin on every site. Locked actions always explain why instead of disappearing.

Working on many sites at once

Sites portfolio

Every client in one view, as a grid or a table: status, ideas waiting, gap to projection, spend against cap and who's online.

Inbox

Everything across my sites that needs me: ideas to approve, held posts, image slots for a person, overdue ledger items, failing CI, invites.

Team

People against sites with each person's role, plus invites. Seat use is shown against the workspace plan.

Site in the URL

Every site screen lives under /s/<site>/…, so two tabs or two people can work on different clients at the same time.

Presence and edit locks

Avatars show who else is on a site. If someone is editing a post, others see "view only" with a take-over option.

Tenant isolation

A site you have no access to is hidden from the switcher and shows "Request access". Tests check that one client's data never appears on another's.

05 · Design system

Glass hierarchy, adapted from the Nawa template

Hierarchy

Page → canvas → soft colour washes → frosted shell → white cards → small chips. One black primary button per region.

Type

General Sans 500 for titles and UI, Poppins 400 for body and meta.

Colour means something

Agent blue machine work · Human amber waiting on a person · Red hard block · Green pass.

Rules are enforced by tests: colours only from tokens, layout that works right-to-left, icons through one registry, WCAG contrast checked. The full kit is shown at /styleguide; the documents are docs/design-system.md and docs/02-design-system.cms.md.

Images and templates

Bring your own image providers

Each site can connect image-generation MCP servers or APIs, plus stock and open-licence sources (Openverse, Wikimedia, Unsplash, Pexels). Keys stay on the server, encrypted. Every candidate records where it came from and its licence.

Bring your own blog template

Developers upload the template as HTML or a zip. The renderer only fills in the structure it found and never invents markup; if a post needs something the template can't show, the post is held instead of shipped wrong.
